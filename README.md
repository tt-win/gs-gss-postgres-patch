# gs-gss-postgres-patch

## 目的
`gs-gss-postgres-patch` 用來管理 PostgreSQL **`gs_gss`** 資料庫的 schema、seed、patch 與 release manifest，目標是同時滿足以下兩件事：

- 可以從最初版本一路重建到最新版本
- 可以從 Jira / 專案單，例如 `TP-1234`，追溯每次 DB 變更

結構與命名慣例對齊 [`gac-mongo-patch`](../gac-mongo-patch)；腳本副檔名為 **`.sql`**，以 **`psql`** 執行。本 repo 是 **`gs_gss` 資料庫 schema／seed 的唯一來源**；`v1.0.0/TP-0000` baseline 最初是從 [`gs-gss-21`](../gs-gss-21) 的 Phase 1 V2（`migration/V2__init.sql`、`dev-seed/V2__phase1_dev_seed.sql`）建立的快照，但該 repo 已移除自己的副本，往後 schema／seed 異動一律只在本 repo 進行。

## 目錄結構
此專案採用「系統正式版號優先，其次依專案代號或 hotfix 類型分類」的結構。

```text
scripts/
  v1.0.0/
    TP-0000/
      ddl/
        000_init_schema.sql
        tables/
        sequences/
      seed/
    version/
      TCG-GS-version-v1.0.0.sql
  v1.0.1/
    TP-1234/
      ddl/
      seed/
      patch/
    version/
      TCG-GS-version-v1.0.1.sql
  v1.0.2/
    hotfix/
      ddl/
      seed/
      patch/
    version/
      TCG-GS-version-v1.0.2.sql

release/
  v1.0.0-TP-0000.lst
  v1.0.1-TP-1234.lst
  v1.0.2-HOTFIX.lst

pending/
  pending-version-assignment/

dev-data/
  tcgdemov3/
```

## 目錄規則
`scripts/` 底下每個版本目錄代表一個正式 DB 發版，例如：

- `v1.0.0`
- `v1.0.1`

資料夾規則如下：

- `v1.0.0` 只能使用 `TP-0000`，代表最初版基線腳本
- `v1.0.0` 之後只能使用 `TP-XXXX` 或 `hotfix`
- `TP-XXXX`：正式專案代號資料夾，用於一般需求版本
- `hotfix`：沒有專案代號、只針對緊急修補的版本資料夾

如果某些腳本尚未確認正式版號、正式歸屬或內容仍待整理，先放在：

- `pending/pending-version-assignment/`

`dev-data/` 用來放開發或 QA 環境專用資料，例如 demo tenant、測試用 seed data。這類腳本不屬於正式 release chain，不應寫進 `release/*.lst`。

## 腳本用途與命名規則
同一個 `TP-XXXX` 或 `hotfix` 底下，可以依用途拆成 `ddl/`、`seed/`、`patch/`。

- `ddl/`：建立 table、修改 constraint、建立 sequence、建立 index，或其他偏結構性的變更
- `seed/`：初始化資料、基礎資料、乾淨環境建置時需要的資料，建議盡量可重跑
- `patch/`：既有環境升版時的資料修補、資料搬移、舊資料格式轉換

如果某一 TP `TP-XXXX` 同時需要 schema、初始化資料與資料修補，可以在同一個 `TP-XXXX` 或 `hotfix` 下同時存在 `ddl/`、`seed/`、`patch/`。

除了 `scripts/v1.0.0/TP-0000/` 的初始基線腳本以外，所有後續版本的 `.sql` 檔名都必須以 **TCG 工作單號** 開頭：

- `TCG-XXXXX-說明.sql`

例如：

```text
scripts/v1.0.1/TP-1234/ddl/TCG-117154-add-gs-config-column.sql
scripts/v1.0.1/TP-1234/seed/TCG-117154-init-gs-config-data.sql
scripts/v1.0.2/hotfix/patch/TCG-117188-fix-invalid-gs-version-data.sql
```

## PostgreSQL 腳本慣例

| 項目 | 慣例 |
|------|------|
| 連線目標 | `gs_gss` 資料庫（`DATABASE_URL` 或 `psql` 連線字串） |
| Schema | 腳本開頭 `SET search_path TO public;`（或指定 schema） |
| 結構變更 | `CREATE TABLE` + `NOT NULL` / `CHECK` / `UNIQUE` |
| 索引 | `CREATE INDEX ... ON table_name (...)` |
| 資料寫入 | `INSERT INTO ...`；可重跑 seed 建議搭配 `ON CONFLICT` |
| 版號紀錄 | 每版收尾寫入 `gs_version`（見「版本腳本規則」） |

每支 SQL 腳本建議開頭設定 `search_path`，並以 `psql -v ON_ERROR_STOP=1` 執行（見下方「執行」）。

```sql
SET search_path TO public;

CREATE TABLE IF NOT EXISTS example (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_time TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 版本腳本規則
每一個正式版號都必須有：

```text
scripts/vX.Y.Z/version/TCG-GS-version-vX.Y.Z.sql
```

這支腳本負責在該版所有 DB 腳本都成功執行後，將結果寫入 `gs_version`。

- `TCG-GS-version-vX.Y.Z.sql` 必須放在該版 `.lst` 的最後一行
- 作用是保留版本歷史，並確保 version 更新只發生在該版腳本全部成功之後

範例：

```sql
SET search_path TO public;

INSERT INTO gs_version (version, description, applied_at)
VALUES (
    'v1.0.1',
    'GS PostgreSQL patch v1.0.1 — TP-1234',
    NOW()
)
ON CONFLICT (version) DO UPDATE SET
    description = EXCLUDED.description,
    applied_at  = EXCLUDED.applied_at;
```

## Release Manifest 規則
`release/` 目錄下，每個 `.lst` 檔代表一個正式版號的上版清單，例如：

```text
release/v1.0.1-TP-1234.lst
```

`.lst` 檔名規則如下：

- 一般需求版：`vX.Y.Z-TP-XXXXX.lst`
- 緊急修補版：`vX.Y.Z-HOTFIX.lst`

`.lst` 檔內只寫 `.sql` 檔名，不寫完整路徑，而且順序就是實際執行順序。以 `#` 開頭的行視為註解，空白行可忽略。

範例（`release/v1.0.0-TP-0000.lst`）：

```text
000_init_schema.sql

currency_codes.sql
currencies.sql
menus.sql
permissions.sql
users.sql
roles.sql
platforms.sql
games.sql
action_logs.sql
gs_version.sql
shedlock.sql

currency-seed.sql
menu-seed.sql
permission-seed.sql
role-seed.sql
user-seed.sql

TCG-GS-version-v1.0.0.sql
```

重要規則：

- 真正的執行順序只看 `.lst`
- `.lst` 中的 `.sql` 檔名必須能在整個 repo 內唯一定位
- version 腳本固定命名為 `TCG-GS-version-vX.Y.Z.sql`，且必須放在該版 `.lst` 的最後一行

## 執行

```bash
export DATABASE_URL=postgresql://user@localhost:5432/gs_gss

# 依 release 清單逐檔執行（範例：v1.0.0 baseline）
while IFS= read -r f; do
  [[ -z "$f" || "$f" =~ ^# ]] && continue
  psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f "$(find scripts -name "$f" | head -1)"
done < release/v1.0.0-TP-0000.lst
```

## 重建策略
如果未來 DB 遺失，或需要從零重建，就依版號順序逐一執行對應的 `.lst`：

1. `release/v1.0.0-TP-0000.lst`
2. `release/v1.0.1-TP-1234.lst`
3. `release/v1.0.2-HOTFIX.lst`

一路執行到最新版本即可。
